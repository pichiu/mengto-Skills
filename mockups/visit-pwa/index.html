家訪 PWA 原型

暗色、大字、無障礙、離線優先的 PWA 原型 —— 展示一套三層授權模型: 資料平面(路線可見範圍)、Admin 平面(事件管理員 vs 系統管理員)、 組織平面(合心/處室管理員)。以花蓮光復堰塞湖溢流風災家訪為情境, 供設計與工程團隊點擊走查每個角色實際看到的畫面差異。

Persona 機制說明

每個 persona 對應一種授權組合,可在 mobile.html / admin.html 右下角的 persona 切換器即時切換,觀察同一份假資料在不同身分下的顯示差異。

  • 行政組 office bypass

    bypass = true,略過路線限制,看整個活動的所有案件 —— 展示「行政角色略過路線範圍」的機制。

  • 訪視志工 visitor ⚠︎ 後端缺口

    只看自己路線 + 可見 PII —— 這是與現行後端不同的預期行為,代表一個後端能力缺口: 現行後端只要不是 bypass 身分,一律拔除 PII 欄位;此原型刻意示範「路線受限但仍需看到完整個案資料」 的實際使用需求,尚無對應後端能力。

  • 指導師父 advisor viewer

    role = viewer,只看自己路線且 PII 被拔除 —— 展示現行後端「viewer 一律無 PII」的既有行為,與 visitor 對照。

  • 被停權 revoked revoked

    revoked = true,登入後看不到任何案件、寫入功能全部關閉 —— 展示帳號停權後的資料平面歸零狀態。

  • 合心/處室管理員 orgAdmin org

    非 bypass、非事件/系統管理員,但擁有 hexinAdminOf / deptAdminOf —— 展示組織平面獨立於資料平面與 Admin 平面的授權:可依組織範圍管理名冊、建立事件;組織樹結構、管理員任免、系統管理員切換為系統管理員專屬。

  • 事件管理員 eventAdmin bypass

    bypass = true 且 eventAdminSlugs 包含 flood-2026 —— 展示 D12 事件管理員:可管單一事件的成員、匯入匯出、規劃桌,但不觸及組織平面。

  • 系統管理員 sysAdmin isAdmin

    adminSignal.isAdmin = true —— 展示 D12 系統管理員:三層平面全部放行,可管所有事件與組織。

三層授權平面

三層各自獨立判斷、可疊加,彼此不是上下屬關係 —— 一個帳號可能同時擁有多層權限的任意組合。

資料平面

bypass / route / viewer
bypass 略過路線限制,看整個活動
route availableRoutes 決定只看被授權路線的案件
viewer role = viewer 或 revoked 一律拔除 PII / 關閉寫入

Admin 平面

D12 事件管理員 vs 系統管理員
事件管理員 eventAdminSlugs 指定的單一事件:成員 / 匯入匯出 / 規劃桌
系統管理員 isAdmin = true:所有事件的建立、管理、規劃桌

組織平面

D13 合心 / 處室管理員
合心管理員 hexinAdminOf:於指定合心範圍管理名冊、可建立事件(組織樹結構為系統管理員專屬)
處室管理員 deptAdminOf:於指定處室範圍管理名冊、可建立新事件(處室字典為系統管理員專屬)
三層獨立、疊加、非上下屬 —— 例如 orgAdmin 可以同時是某條路線的 member,兩層權限互不覆蓋、互不推導。

設計理念

暗色、大字、無障礙 ≠ 樸素。這個原型刻意保留層次、字體節奏與有意義的動效, 證明「可及性」與「有設計感」不衝突。

層次

surface / surface-raised 兩級底色搭配漸層描邊卡片與柔和陰影,建立深度而不靠死黑對比。

字體節奏

18px 基準字級、1.6 行高,標題到內文有明確的比例級距,長篇個案資料也能舒適閱讀。

有意義動效

轉場、同步脈動點只在傳達狀態變化時出現,並尊重 prefers-reduced-motion。

路線色票系統

每條路線一個高對比色票(route-a 到 route-e),在列表、地圖、規劃桌間保持一致辨識度。
