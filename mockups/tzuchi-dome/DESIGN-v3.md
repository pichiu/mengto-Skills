# Mockup v3 — 審核 / 活動 / 名單 / 座位 / 交通 精修(Opus 規劃)

延伸 v1+v2。沿用同一份響應式 PWA、同套 tokens、深色大字、persona 切換器與所有 bans。
**不重寫既有視覺語言,只按下列 15 點精修。** 分三階段(Sonnet 依序實作,同一 `index.html`)。

共用新增:
- `DEMO_NOW`(常數,如 `2026-11-09T10:30`)= 展示用「現在」時鐘,讓活動能同時出現
  進行中/即將發生/已發生三種狀態。UI 需標「Demo 時鐘」小字。所有時間比較用它。

---

## 階段 1 — 活動 + 審核(第 1–7 點)

### 1) 審核頁 `/approvals`(新)
- 導覽新增「審核」,cap gate:`manage_users` 或(`crud_registration` 且 scope)。
  → 合心行政、和氣行政、和氣人事看得到;純活動/純聯區行政看不到。
- 內容:個人帳號綁定審核。
  - **待審核**清單:申請人 email、綁定的 person(姓名+和氣)、申請時間、[核准]/[婉拒]。
  - **已核准**清單:email、person、核准人、核准時間、ICS 狀態。
  - scope 過濾(和氣角色只審自己和氣的申請)。核准=mock 產生 ics_token 提示。
  - 空狀態:「目前無待審核申請」。

### 2) 活動排序 + 分組
- 依「起始日期時間」排序,分三組並各自標頭:
  - **進行中**(DEMO_NOW 落在起迄之間)—置頂、醒目。
  - **即將發生**(起始 > DEMO_NOW)—依時間近→遠。
  - **已發生**(結束 < DEMO_NOW)—**可折疊**(預設收合),依時間近→遠。
- 每組顯示計數。

### 3) 新增活動表單 — 增欄位
- 既有 type/title/location/heQi/days + **新增**:
  - **場次**(session,4 選 1 或「不限/全區」)
  - **演繹區塊**(block,A/B/C 可複選或「全部」)
  - **起始時間 / 結束時間**(datetime,支援跨日多日)
- 依角色鎖範圍(和氣活動 heQi 鎖自己)不變。

### 4) 活動 編輯 / 取消
- 每個活動(有 `manage_events_*` 且 scope 通過)顯示 **編輯**(開同表單帶入現值)+ **取消活動**
  (二次確認;取消後標「已取消」樣式,不刪列)。
- 已有點名紀錄的活動,取消需提示(mock 擋或警告)。

### 5) 點名狀態改為三態
- 點名 toggle = **未到 / 已到 / 請假**(取代舊 未到/現場/車上)。
  - 未到=中性、已到=`--ok`、請假=`--warn`(或中性描邊)。三態互斥、大按鈕、≥48px。

### 6) 依時態決定 報名 vs 點名
- 活動明細動作依該活動時態:
  - **即將發生** → 顯示「**報名**」介面(每人:報名 / 請假,見第 7 點),**不可點名**。
  - **進行中 / 已發生** → 顯示「**點名**」介面(未到/已到/請假)。
- 明細頁頂部標示目前模式(報名中 / 點名中)+ Demo 時鐘。

### 7) 活動報名
- 即將發生活動的名冊:每人狀態 **報名 / 請假**(預設報名或待定),可切換。
- 顯示已報名/請假/未回覆計數。scope 決定可改誰。

## 階段 2 — 名單 + 座位(第 8–12 點)

### 名單(第 8–11 點)

#### 8) 手機改 deck view
- **手機(<1024px)**:每人一張卡(deck),而非表格橫排。卡上分行排版關鍵欄位。
- **桌面(≥1024px)**:維持表格(但加下列新欄位)。

#### 9) 新增人員按鈕
- 「＋ 新增人員」按鈕,cap `manage_staff`(合心人事/合心行政)可見;開 mock 表單
  (姓名/性別/和氣/聯區/category=工作人員…)。無權限不顯示。

#### 10) 顯示 演繹區塊 / 服裝 / 位置
- 每人(每場報名)顯示:**區塊**(A/B/C)、**服裝**(藍/白,C 組無)、**位置**`{列}-{排}`(未配位顯「未排」)。

#### 11) 多場次報名呈現(重點)
- 一人可報 1–4 場。名單核心資訊 = **報了幾場** + **每場的位置**。
- **資料模型**:每人 `participations: [{session, block, costume, seat:'48-21'|null, is84}]`(0–4 筆)。
- 呈現(「全部場次」檢視):
  - 卡片/列顯示「報 N 場」徽章 + 每場一個小 chip:`場次簡稱 · 區塊 · 服裝 · 位置`。
  - 選特定場次篩選時,只顯示該場那筆的區塊/服裝/位置。
- 場次簡稱:11/12 共同 · 11/13 安平+大橋 · 11/14 佳里 · 11/15 仁德。

### 座位(第 12 點,完整標示化)
把座位格做成**真實可讀的球場圖**(西一象限 A+B):
- **座標**:列 1–54(列1 最右)、排 16–22(排16 最上)。渲染 `gridColumn=55−列`、`gridRow=排−15`。
- **每格顯示座位號** `{列}-{排}`(桌面同時 name+和氣;手機點擊或縮小顯號)。
- **軸標**:**上方一列顯示列號**(1..54,對齊每格)、**左方顯示排號**(16..22)。
- **每 3 列一組的標籤帶**(顯示於格區上方或組首):`{A/B}` · `{藍/白}` · `{男/女}`。
  - **區塊**:A=列1–30、B=列31–54。
  - **服裝**:`f(列)` 每 3 列 白/藍 交替(白白白藍藍藍…),與資料一致。
  - **性別**:**列1–12 與 列49–54 = 男**,其餘(列13–48)= 女。
- **缺角(關鍵,湊成 368)**:排 16–22 共 7 排 × 54 列 = 378,扣除截角 10 格 = **368**:
  - 列51 只到排21(缺排22)· 列52 只到排20(缺21,22)· 列53 只到排19(缺20,21,22)· 列54 只到排18(缺19,20,21,22)。
  - 這些缺格**不渲染**(或渲染為空白佔位,非可選座位)。頁面標「本象限 A+B 共 368 席」。
- 圖例:白/藍服裝、空位、我的座位、男/女(可用軸標帶表達)。
- 手機可橫向捲動(容器 `overflow-x:auto`),body 不橫捲。桌面完整展開。

## 階段 3 — 交通(第 13–15 點)

### 13) 車長點名移出「我的」→ 交通
- 從 `leader` persona 的「我的」頁**移除**車長工具卡。
- 給 `leader` persona 一個 **交通** 導覽項(特例:個人但 busLeader → 導覽加「交通」)。
- leader 的交通頁 = **車長點名**視圖(只有本車):乘客名單、司機聯絡(姓名/電話/車牌)、
  **上車點名**(未到/已到 逐人 toggle)、撥打(乘客/司機)。
- 幕僚的交通頁維持 v2 三階(上車點調度 / 車輛分配 / 乘客編排)。

### 14) 同車去回 + 跨場次去回不同車(合心調度)
- 預設:**同車去回**(一位乘客去程與回程同一台,同上下車點)。
- 例外:到高雄靜思堂彩排/驗收,一天可能 **2 或 4 個場次** → **跨場次**參與者可能
  **去程、回程搭不同車**(但**同一上下車地點**)。整日型(企劃/菁英/工作人員)與跨場次者
  由 **合心** 統一安排。
- Mockup 呈現:
  - 乘客資料加 `dayType: '單場'|'跨場次'|'整日'` 與 `outboundBusId` / `returnBusId`(可不同)。
  - 去/回程 toggle 已有;在 **合心(交通幹事)** 視圖新增「**跨場次 / 整日調度**」區:
    列出這類乘客,分別指派**去程車**與**回程車**(同上下車點),標示 去≠回。
  - 一般單場乘客顯示「同車去回」標。

### 15) 交通幹事填司機資料
- 新增/編輯車次表單(交通幹事)加欄位:**司機姓名**、**司機電話**、**車牌**(車牌可選填)。
- 車牌顯示於車次卡與車長視圖;司機電話維持敏感(僅調度/車長可見)。

## 驗證要求(每階段)
- 沿用 v1/v2 tokens/元件/動效;新元件遵守所有 bans、每互動元件備齊狀態、對比 ≥4.5:1、
  切換 150–250ms(prefers-reduced-motion 有替代)。
- 每個相關 persona × 畫面截圖驗證(手機 390×844 + 桌面 1440×900):
  項目正確、時態分組正確、報名/點名依時態切換、名單 deck/表格與多場次呈現、
  座位軸標+缺角(數到 368)、交通車長視圖與司機/車牌欄位、無橫向溢出、無 console 錯誤。
- 假資料一致:大橋和氣名冊沿用;為部分人加多場次 participations;高雄彩排車次加司機/車牌。
