01 / quick recipe

Hero entrance (stagger)

Elements tagged data-anim inside .hero fade and rise into place on page load, staggered by 0.06s each.

gsap.from(".hero [data-anim]", { y: 24, autoAlpha: 0, duration: 0.8, ease: "power2.out", stagger: 0.06, });

Motion that feels considered
Every element enters with the same easing curve and a small stagger, so the hero reads as one composed moment rather than a pile of separate animations.

02 / quick recipe

Sequenced timeline

A single timeline with shared defaults chains three tweens, each new tween starting slightly before the previous one finishes via a negative overlap position.

const tl = gsap.timeline({ defaults: { ease: "power2.out", duration: 0.6 } }); tl.from(".nav", { y: -20, autoAlpha: 0 }) .from(".hero-title", { y: 30, autoAlpha: 0 }, "-=0.2") .from(".hero-cta", { scale: 0.95, autoAlpha: 0 }, "-=0.2");
HomeWorkAboutContact
Timelines orchestrate, tweens execute.
tl.play()
The "-=0.2" position parameter means each tween starts 0.2s before the previous one ends — a small overlap that keeps the sequence feeling continuous instead of stepped. This timeline replays once, the moment this section enters the viewport (ScrollTrigger, once: true).

04 / scroll-driven storytelling

Scroll-triggered fade + rise cards

Each card animates in independently as it crosses into the viewport, using its own ScrollTrigger instance — no markers, no manual scroll listeners.

gsap.from(card, { y: 40, autoAlpha: 0, duration: 0.7, ease: "power2.out", scrollTrigger: { trigger: card, start: "top 85%", end: "top 40%", toggleActions: "play none none reverse", }, });

05 / performance-friendly properties

autoAlpha fade-ins

Only transforms and opacity/autoAlpha are animated here — never top/left/width/height, which force layout and cause jank.

gsap.from(".autoalpha-grid .card", { autoAlpha: 0, y: 16, duration: 0.5, stagger: 0.04, scrollTrigger: { trigger: ".autoalpha-grid", start: "top 80%" }, });
opacity: 0 → 1
visibility: hidden → visible
transform: translateY
no reflow

autoAlpha animates opacity and toggles visibility in one property, so hidden elements don't intercept clicks. Combined with will-change: transform on actively animating cards, the browser can composite these on the GPU instead of recalculating layout every frame.

06 / quick recipe

Scroll-scrub pinned section

The .story section pins itself to the viewport for 800px of scroll distance while its panels translate horizontally, scrubbed directly to scroll position.

gsap.timeline({ scrollTrigger: { trigger: ".story", start: "top top", end: "+=800", scrub: 1, pin: true, }, }).to(".story .panel", { xPercent: -200 });
01 / 03

Pin

The section locks in place at the top of the viewport once its top edge reaches "top top".

02 / 03

Scrub

Scroll position drives the timeline directly — scrub: 1 adds a 1s catch-up smoothing lag.

03 / 03

Unpin

After 800px of additional scroll, the section releases and normal scrolling resumes.
